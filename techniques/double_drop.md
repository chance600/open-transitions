# double_drop

**Bank:** T-024 · **Automatability:** ADAPT · **Confidence:** medium

**Source:** null-set-ai-dj (MIT); drop-pair complementarity is curatorial

## Signature

```python
double_drop(a, b, sr, bar_s, drop_at_bar=16, drop_bars=16)
```

## Spec

Two builds converge on ONE downbeat. Single-sub-bass rule enforced:
B's lows stay killed through the drop; bass swaps after drop_bars.

a, b: build+drop segments, SAME length, builds starting together
    (caller aligns). drop_at_bar: bar index (0-based) of the drop.
Prerequisite (caller's taste call): at most ONE drop carries a vocal.

## Axes (Phase 23, genre traditions tranche A)

**Converge exit** — the second outcome of the "running up a
mountain" pattern (kohadachan, note.com, fetched 2026-10-22):
align the drops and set a mix start 8/16 bars before them, then
either make the double drop OR converge on the drop of the next
track — A's build becomes the ramp and only B's drop sounds.
Same staging, different landing: the alignment is the work,
the collision is optional.

**Triple-drop staging (deck_count = 3)** — three drops aligned
on one downbeat, documented as an Andy C case study in the same
taxonomy (Sub Focus "Rock It" (Wilkinson Remix) + Camo &
Krooked "Sientelo" + Sub Focus "Solar System"). Rendered as this
base composed with three_deck_layer (T-020): the third drop is
staged by the layer, the single-sub rule extends to two of the
three drops running lows-killed. DJGear2K's guide names the
general form (multi-channel drop mashups, up to four tracks,
prepared not improvised).

**Chop continuation** — after the landing, ownership of the
fused drop can alternate between the tracks instead of holding:
that continuation is its own base, drop_chop (WEB-20).
